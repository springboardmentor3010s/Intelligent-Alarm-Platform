# Intelligent Cognitive Alarm Platform

AI-powered alarm platform that requires solving cognitive challenges before dismissing alarms.

## Tech Stack (All Free & Open Source)
- **Backend**: Python 3.11, FastAPI, SQLAlchemy, Alembic
- **Frontend**: React 18, Tailwind CSS, Chart.js
- **Databases**: PostgreSQL 16, MongoDB 7
- **Cache**: Redis 7
- **Containers**: Docker & Docker Compose

## Quick Start (Docker — Recommended)

```bash
docker-compose up --build
```

- Frontend: http://localhost:3000
- Backend API: http://localhost:8080
- API Docs (Swagger): http://localhost:8080/docs

This starts PostgreSQL, applies Alembic migrations automatically, and serves the built frontend via Nginx.

## Manual Setup

### Backend
```bash
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
alembic upgrade head
uvicorn app.main:app --reload --port 8080
```

### Frontend
```bash
cd frontend
npm install
npm run dev
```

## Challenge Types
- Math, Logic, Memory, Word Game, Pattern, Riddle, Quiz

## Habit Score Formula
```
Habit Score = Wake-Up Consistency (35%)
            + Challenge Completion (25%)
            + Snooze Reduction (20%)
            + Sleep Schedule Adherence (20%)
```

## Additional Modules
- **Notifications** — bedtime/wake-up reminders, habit alerts, missed-alarm alerts, generated by an in-process APScheduler job (every 15 min) plus on-demand via `GET /notifications`.
- **Reports & Export** — `GET /reports/habit/pdf` and `GET /reports/habit/xlsx` produce a habit-score + challenge-history report (ReportLab / OpenPyXL). Export buttons are on the Habit Dashboard.
- **ML Difficulty Model** — `backend/app/ml/difficulty_model.py` (XGBoost) with a rule-based fallback. Train with `python -m app.ml.train_difficulty_model --demo` (synthetic data) or without `--demo` once enough real usage data exists. Status: `GET /ml/status` (admin only).

## Database Migrations
Schema is version-controlled with Alembic (`backend/alembic/`). Run `alembic upgrade head` before starting the app (already wired into `backend/Dockerfile`'s container entrypoint).

## OAuth2 Social Login
Google and GitHub "Continue with..." login is implemented end-to-end (`backend/app/api/oauth.py`, `backend/app/core/oauth.py`) but ships **unconfigured** — the login buttons stay hidden until you add real credentials:

1. Google: create an OAuth client at [console.cloud.google.com/apis/credentials](https://console.cloud.google.com/apis/credentials); GitHub: create an OAuth App at [github.com/settings/developers](https://github.com/settings/developers).
2. Set the authorized redirect URI to `http://localhost:8080/auth/oauth/<google|github>/callback`.
3. Fill in `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` and/or `GITHUB_CLIENT_ID`/`GITHUB_CLIENT_SECRET` in `backend/.env`.
4. Restart the backend — `GET /auth/oauth/providers` will report the provider as available and the frontend buttons appear automatically.

New/existing accounts are matched and linked by email automatically; OAuth-only accounts have no password and can't use the password login form.
